## 缩略图删除回归

GitHub 验收暴露了跨存储策略重复图片的缩略图误删问题：缩略图按 MD5 和输出格式全局共享，原来的删除逻辑只检查当前策略中的引用。删除另一个策略下的图片可能使仍被引用的缩略图返回 404；容器重建后的检查才发现丢失。

已在旧生产镜像的真实 HTTP 请求中复现，并通过 PHP 回归测试确认。修复后，原图仍按策略判断引用，缩略图在全站没有其他引用时才删除。原先 PNG 的重新编码可能使哈希随编码时间变化，未稳定覆盖这个场景；验收新增不经重编码的固定 SVG，并检查删除重复图片后、容器重建后缩略图均可访问。

修复后的完整 HTTP/Chromium/持久化验收、三种数据库测试及语法检查均通过。本次没有在本地运行 GitHub 工作流。

## 验证限制

- 当前没有外部服务测试凭据。阿里云 OSS、腾讯云 COS、七牛、又拍云、商业云审核和真实云邮件供应商未进行厂商联调。
- Moto 验证 S3 HTTP 协议适配，不代表已验证 AWS S3 或真正的 MinIO 实例。SMTP 验证本地协议投递，不代表公网送达。
- 审核服务和远程更新元数据使用固定响应验证应用处理逻辑，未执行真实云审核或上游在线升级。
- SQL Server 没有安装对应驱动，未测试；没有声称其可用。
- 本地仅验证 amd64。arm64 构建、Docker Hub 推送、SBOM 和构建证明须由 GitHub 工作流实际执行后确认。
- 浏览器拖放与粘贴使用合成事件，文件字节实际上传到生产容器；未覆盖操作系统文件管理器拖拽和所有浏览器组合。

这些边界不属于已通过测试；部署时应使用实际供应商、凭据及目标架构补充验收。
